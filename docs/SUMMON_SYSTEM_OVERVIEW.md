# 召唤兽系统概览 (Summon System Overview)

## 1. 核心设计理念

本项目的召唤兽系统围绕着**"模板化生成"**和**"多途径获取"**两个核心理念构建。所有召唤兽都源于一个统一的配置文件，确保了数据的一致性和可维护性。玩家可以通过多种游戏内机制（如野外捕捉、孵蛋、融合）获得这些召唤兽，每种途径都为召唤兽的最终形态带来了不同的可能性。

## 2. 关键文件与数据结构

### 2.1. 召唤兽模板: `src/config/summon/allSummons.json`

这是整个召唤兽系统的 **唯一数据源**。它定义了每一种召唤兽的基础模板。

- **关键字段**:
    - `id`: 召唤兽的唯一标识符，例如 "vampire"。
    - `name`: 显示名称，例如 "吸血鬼"。
    - `creatureType`: 生物类型，通常为 `"summon"`。
    - `isCapturable`: 是否可被捕捉。
    - `fiveElement`: 五行属性 (金, 木, 水, 火, 土)。
    - `quality`: 基础品质 (如 `normal`, `rare`, `epic`)。
    - `growthRates`: **核心成长率**，决定了升级时各项一级属性的成长潜力。
    - `basicAttributeRanges`: **初始一级属性范围**，在生成时会在此范围内随机取值。
    - `guaranteedInitialSkills`: **必带技能**，生成时必定拥有的技能。
    - `initialSkillPool`: **可选技能池**，会根据 `initialSkillCountMean` 和 `initialSkillCountStdDev` 通过正态分布采样，随机赋予若干技能。

### 2.2. 类型与配置: `src/config/enumConfig.js`

该文件定义了与召唤兽相关的各种枚举和配置。最核心的是 `SUMMON_NATURE_TYPES`。

- **`SUMMON_NATURE_TYPES`**: 定义了三种召唤兽自然类型，极大地影响了召唤兽的最终强度。
    1.  **🌿 野生 (Wild)**:
        -   **特点**: 拥有初始等级，即战力。
        -   **劣势**: 属性和成长率无加成，潜力最低。
    2.  **👶 宝宝 (Baby)**:
        -   **特点**: 从0级开始，基础属性和成长率有显著提升，并有额外潜力点。
        -   **优势**: 培养上限远高于野生。
    3.  **🧬 变异 (Mutant)**:
        -   **特点**: 从0级开始，拥有最高的属性和成长率加成，以及最多的额外潜力点。
        -   **优势**: 潜力 সর্বোচ্চ，是追求极限的玩家的目标。

## 3. 召唤兽生成逻辑

系统提供了多种生成召唤兽的途径，主要通过一个统一的工厂函数 `createCreatureFromTemplate`（推断）实现。

### 3.1. 主要生成途径

1.  **炼妖/直接生成 (`refineMonster` in `src/gameLogic.js`)**:
    -   这是一个基础的生成方式，通常用于测试或简单的奖励发放。
    -   它会从 `allSummons.json` 中随机选择一个模板，并创建一个等级为1的实例。

2.  **孵化 (`Incubator` in `src/features/incubator/systems/incubator.js`)**:
    -   玩家将各种"蛋"放入孵化器。
    -   `eggConfig.js` 定义了不同类型的蛋及其可能孵化出的召唤兽列表。
    -   孵化完成时，会从可能列表中随机选择一种召唤兽，并根据蛋的品质（`eggQuality`）随机生成召唤兽的最终品质。

3.  **融合 (`SummonFusionManager.js`)**:
    -   这是最复杂的生成方式，允许玩家将两只召唤兽合成为一只新的召唤兽。
    -   **后代物种**: 通常会随机继承父母其中一方的物种。
    -   **属性遗传**: 后代的裸体属性和成长率由父母双方的数值，结合特定公式计算得出。
    -   **技能遗传**: 父母的技能会根据一定的概率遗传给后代。
    -   **`natureType` 遗传**: 后代的自然类型（野生/宝宝/变异）也由父母的类型决定。
    -   **材料影响**: 玩家可以添加辅助材料来影响合成结果，例如提升成功率、指定五行属性等。

## 4. 实例管理

尽管未在搜索结果中直接体现，但根据项目结构推断，`src/store/SummonManager.js` 是一个核心的管理类。它负责：

-   持有当前游戏中所有召唤兽的实例。
-   提供对召唤兽实例的增、删、改、查接口。
-   处理召唤兽的升级、学习技能、穿脱装备等核心逻辑。
